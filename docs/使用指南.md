# 音乐推荐使用指南

适用版本：1.0.1。安装见 [README](../README.md)，默认值见 [配置参考](配置参考.md)。

## 让模型搜歌

启用音乐搜索后，插件注册 `search_music` 工具。自然地提出歌名、歌手或主题，例如“帮我找《晴天》”“推荐两首轻快的歌”。模型需要具备并开启工具调用能力，才能实际调用。

工具接收关键词与可选数量；未给数量时使用配置默认值，实际结果数仍受搜索上限与平台返回值影响。情绪和主题也只是搜索关键词，不是经过专门训练的音乐情绪分类。

本插件没有独立搜索指令，也不保证模型在每次提到音乐时调用。检查日志中的工具调用可以区分模型没调用与搜索本身失败。

## 选择发送方式

| 页面选项 | 保存值 | 使用条件 |
|---|---|---|
| 歌名与播放链接 | `link` | 不需要卡片签名；适合先验证搜索和工具调用 |
| 音乐卡片（机器人签名服务） | `card` | QQ适配器支持音乐消息，机器人协议端配置了可用的音乐签名服务 |
| 音乐卡片（独立签名服务） | `card_api` | 填写可用的独立签名地址与密钥，协议端支持相应卡片消息 |
| 本地音乐卡片（实验） | `ark` | 本地构造卡片；QQ是否接受受令牌、协议端和服务端规则影响 |

### 歌名与播放链接

插件把搜索结果交给模型组织回复。可选择包含专辑、时长和播放页面链接。链接是否展示还受模型最终表达影响。

### 机器人签名卡片

签名服务在机器人协议端配置，并非在插件的“独立签名卡片”分组配置。网易云通过歌曲ID构造音乐消息，QQ音乐通过歌曲页面、标题等信息构造卡片；最终样式与可播放情况由协议端、签名服务和QQ处理决定。

### 独立签名卡片

填写服务地址、密钥，以及服务需要时的格式参数。页面中的默认地址只是现有默认配置，不表示已经具有访问资格或服务一定可用。保留服务方要求的参数，密钥不要写到公开文档或分享截图中。

### 本地实验卡片

本地构造卡片，支持令牌、来源标识和应用编号配置。空令牌的本地生成方式不保证被QQ接受。普通使用先选择链接或有可用签名的卡片，不把实验方式当作稳定的签名替代方案。

卡片全部发送失败时，工具返回歌曲文字信息供模型继续说明；发送部分成功时返回已发送数量。是否在最终回复中完整展示链接取决于展示设置和模型。

## 数量与等待

“默认搜索数量”是未指定数量时的结果目标，“一次搜索的歌曲数量上限”是硬上限，“每次最多发送的卡片数”控制卡片模式。搜索结果少于目标时以平台实际返回为准。

搜索最长等待只控制相关请求的等待，不保证外部平台响应。切换音源或卡片方式后保存并重载插件。

## 常见问题

**AI只口头推荐，没有搜索？** 检查模型工具调用能力、框架工具开关与“启用音乐搜索”，再查 `search_music` 是否实际执行。

**搜索失败或没有结果？** 检查服务器能否访问所选音源、等待时间和关键词，尝试明确歌名或歌手。

**卡片发不出来？** 先改链接模式验证搜索。如果链接正常，再检查当前卡片方式的签名服务、密钥、协议端和发送日志。

**卡片不能直接播放？** 搜索返回的信息不等于可播放音频授权，实际呈现受音源、QQ和签名方式影响，可使用歌曲页面链接。

**配置改了还用旧方式？** 保存后重载插件；设置在插件初始化时读取。
